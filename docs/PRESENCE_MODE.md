# 常驻感知

常驻感知在后台整理符合条件的群消息，保存观察、未结束的话题和群内习惯，供后续聊天参考。它本身不发送消息，也不直接决定是否回应。

## 开启与查看

在“模型 → 对话与上下文”中打开“常驻感知”，对应设置为 `presenceEnabled`。新安装默认关闭。打开后，同页可以查看心情、关注和各群观察状态。

该功能只处理已启用的 mention、light、natural 群中通过入口检查且未处理过的消息；私聊、silent 群和 osu-only 群不参与观察。

## 后台处理

待处理消息按批送给模型，每批最多 8 条。达到 6 条时尽快处理，不足时约 45 秒后尝试处理。积累至少 8 条观察且距离上次整理至少 20 分钟后，可以进一步整理心情、人物印象和话题。

同一群的批处理和整理分别防止重复并发执行；失败后等待 5 分钟再尝试。消息、观察和话题都有容量限制，避免后台队列持续增长。模型提出的消息 ID 和人物必须来自实际提供的记录。

API 模式使用当前配置的模型名，并移除名称末尾的 `-eco`。Codex 通道按其适配器的模型配置执行。

## 对对话和自主阅读的影响

回复提示可以包含当前群少量相关观察。其他群的原始消息与人物细节不会借此直接展示。观察可能影响后续表达，但回复仍受原来的参与判断、群模式和发送频率限制。

开启常驻感知还会使自主阅读跳过每日 Token 上限；唤醒次数、间隔和单次请求限制继续生效。自主阅读需要另行开启，详见[人格、关系与自主阅读](PIPPI_PERSONALITY.md#自主阅读)。

常驻感知与[按需消息查询](pippi-awareness.md)用途不同：前者整理群聊背景，后者查询具体发送事实。查询自己的发送档案仍由模型选择工具触发。

## 维护

`GET /api/presence` 提供状态，沿用控制台认证。具体过滤、模型选择和队列限制见 [presence.ts](../server/bot/presence.ts)。

```powershell
npm run presence:verify
```

验证覆盖默认关闭、消息去重、整理、来源检查和提示中使用观察的范围。
