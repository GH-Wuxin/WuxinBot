# 人格、关系与自主阅读

在“人设”页调整 pippi 的身份和表达，在“接话与好感”页启用社交功能、查看关系与经历。新安装默认关闭社交功能和自主阅读。设置中的人格、人物关系和实际消息记录分别保存。

## 接话与关系

模型结合当前会话判断是否回应、回应谁，以及互动是否值得更新关系。普通成员被 @ 或叫名字时仍可能得到沉默；Owner 的身份由配置和实际发送者确认，其正常明确请求受到优先处理。群头衔、自称或模型输出不会授予 Owner 权限。

普通成员的好感范围为 0–100，熟悉程度另行记录。Owner 显示为“特殊”，不参加普通分数排名。好感和熟悉程度可以跨会话共享；会话情绪、摘要、称呼及表达偏好按范围保存。

关系更新在后台检查依据和版本，再写入数据库。模型未提出变化、依据失效或结果不符合约束时，可以不更新。普通回复不等待全部后台整理结束，发送流程见 [功能与消息查询](pippi-awareness.md)。

Owner 可使用以下指令，具体权限仍以运行时检查为准：

| 指令 | 用途 |
| --- | --- |
| `/w 好感度 [@成员或QQ]` | 查询关系 |
| `/w 好感榜` | 查看本群排名 |
| `/w 好感榜 全局` | 查看全局排名 |
| `/w 指令 set 名称 内容` | 设置当前会话的长期指令 |
| `/w 指令 revoke 名称` | 撤销长期指令 |
| `/w 指令 list` | 查看当前会话的长期指令 |

长期指令保留实际作者、来源消息、版本和撤销记录。普通聊天、引用文本和记忆不会自动变成长期指令。

## 近况与经历

“Pippi 的近况与经历”面板显示心情、正在关注的事、短经历及其来源。可以校正或忘记经历、结束关注。校正和删除也会处理依赖旧记录的关注和心情，避免继续引用失效依据。

经历必须来自真实聊天或成功读取的资料。每条经历分别保存事实与看法，并保留可核对的来源；未发送草稿不能记成已分享。系统最多保留 5 项关注和 1,000 条短经历。

群聊与私聊经历只在允许的会话范围使用。主动阅读的公开资料可以跨群使用，但后续聊天仍分别记录。对话提示可以包含少量相关近况与经历；自己的发送档案另由工具按需查询，不会每轮加载。

## 自主阅读

在“接话与好感 → Pippi 的近况与经历”中开启自主阅读。还需要启用社交功能、[osu! 官方搜索](OSU_SEARCH.md)，并提供有效的 osu! API 配置。全局暂停或节能模式会暂停新活动。

程序运行期间每 10 分钟检查新闻、lazer 更新及配置的公开论坛板块列表。取得新资料后，模型选择是否进一步阅读、记录或分享。列表查询不使用模型；没有合适资料时可以不发起推理。

| 设置或限制 | 当前行为 |
| --- | --- |
| 每日唤醒次数 | 初始值 3，可在面板调整 |
| 两次唤醒间隔 | 至少 10 分钟 |
| 每轮调用 | 最多 3 次模型请求、2 次资料工具调用，分享也计入其中 |
| 请求时限 | 单次 20 秒，整轮 90 秒 |
| 单次生成 | 上限 2,048 Token，包含模型思考 |
| 群内主动分享 | 仅近期有交流的 natural 群；每群每日最多尝试一次，全局最多两次 |

开启[常驻感知](PRESENCE_MODE.md)时，自主阅读不执行每日 Token 上限；次数、间隔和单次请求限制仍生效。未开启常驻感知时，使用面板设置的 `pippiActivityDailyTokens`，初始值为 30,000。日期按 Asia/Shanghai 划分。它只控制该后台功能，不是整个项目的 API 消费预算。

状态面板区分已确认用量、缺失用量信息和在途请求。调用失败或进程中断时仍保留计数，以便核查。当前 Codex 适配器无法强制单次输出上限，因此自主阅读不会使用该通道。

模型可以读完后不记忆、不改变心情或不分享。只有收到成功发送回执才记录已分享；群模式变化、优先请求或经历被修改时会放弃过时草稿。

## 维护与验证

相关实现为 [社交状态](../server/bot/social/state.ts)、[自身经历](../server/bot/social/self.ts)、[后台关系整理](../server/bot/social/reflection.ts)和[自主阅读](../server/bot/activity.ts)。这些状态保存在 profiles 分片，控制台的逻辑数据库备份会包含它们。备份方式见 [README](../README.md#数据与隐私)。

```powershell
npm run social:v2:verify
npm run osu:search:verify
npm run pippi:awareness:verify
```

测试使用隔离数据和模拟接口，检查权限、来源、会话范围、更新冲突、删除、请求中断与实际发送确认。
