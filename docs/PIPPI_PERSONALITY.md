# Pippi 的近况、经历与自主阅读

Pippi 的身份与性格继续由现有人格设置维护。新的 `socialV2.self` 保存她当前的心情、最多 5 项关注和 1,000 条短经历；真实聊天、实际读取成功的 osu! 资料可以成为依据。LLM 决定是否记忆、改变心情和回应，不用关键词、正则或固定好感阈值代替语义判断。

普通成员的 @ 和叫名字仍由同一接话评估决定，可以沉默。每次新交流都会重新评估；友善或正常交流可以先恢复回应，不要求先涨回某个分数。Owner 由代码识别、永久特殊，正常明确请求仍受保障。`/w info`、`/w compare`、`/w update` 等功能指令保持原路径。群聊默认短句、自然标点，不会因被提及自动改成长解释。

## 经历与隐私

- 记录只接受宿主提供的消息 ID 或成功阅读的内容版本 ID。事实和看法合计最多 200 字，不以标题列表、失败读取或未发送草稿冒充完成的经历。
- 群聊和私聊记录只在相同范围使用；由对话发起的阅读也保留在当前范围。自主公开阅读可以跨群使用，后续群聊独立保存。其他范围只能看到有限类别的抽象心情，不携带原群人物和原因。
- 接话判断和回复分别注入同一套范围过滤的近况与至多 3 条经历，序列化文本最多 2,200 字符。范围、参与者、当前关注和新近程度用于选取小窗口，模型理解相关性。
- 自身状态、人物关系和会话感受分别检查版本；过时的模型结果放弃相应更新，不付费重算。重复来源不重复建经历。
- 控制台可结束关注、校正或忘记经历。校正/忘记同时清除依赖它的旧关注和心情；旧来源不能立即重建被忘记的结论。最多保留 2,000 个来源删除标记。
- 记录实际分享需要发送回执确认。未知结果或失败不标记为已分享，不自动重复发送。资料、记忆和状态提案不能写入 Owner 身份、权限或固定人格。

## 自主活动与额度

在「社交 → Pippi 的近况与经历」设置，新安装默认关闭。运行中的程序每 30 分钟采集新闻、lazer 更新和已配置公开论坛板块的近期列表；只采集元数据不使用模型。没有新资料或未完公开关注就不唤醒，不补跑停机期间的任务，不唤醒电脑。

| 边界 | 默认行为 |
| --- | --- |
| 唤醒 | 最多 3 次/日，间隔至少 4 小时 |
| 后台日额度 | 30,000 Token；按 Asia/Shanghai 分日 |
| 单次活动 | 最多 3 次模型请求、2 次 osu! 资料工具调用 |
| 思考/生成 | low，遵守现有思考总开关；`max_tokens=2048` 包含思考 |
| 调用期限 | 单请求 20 秒，整轮 90 秒；不做 SDK 重试或空输出重试 |
| 群内开场 | 仅已启用 natural 群，近 20 分钟有交流；单群每日最多尝试 1 次、全局最多 2 次 |

模型可以不读、不记、不改变心情。阅读后的主动分享仍需模型判断当前群聊是否适合，受原群冷却和回复上限约束；复用现有协调器，使用独立的 `pippi-activity` 来源，不能冒充用户或 Owner。群聊出现新动向、优先请求、经历被修改或群模式变化时放弃旧草稿。light、mention、osu 模式不增加自主开场。一次活动若已用完三次模型请求，就没有额外的分享请求。

调用前按输入 UTF-8 字节、工具定义、模块补充和输出上限保守预留额度；有 usage 则按实际总量结算，思考不重复累加。失败或缺少 usage 按预留计入未知消耗；重启后在途预留也按未知结算。额度不够时停止新增调用。供应商不遵守输出上限或用量报告错误仍可能导致单次超额，后续调用会停；Codex App Server 当前无法约束此项输出，选择该通道时自主阅读暂停并展示原因。前台聊天成本单独统计。

关闭自主阅读只停止后续活动，已有经历仍可用于聊天。停机时中止活动并等待现有后台任务退出。模块复用现有后台并发名额，让前台排队优先；没有新的队列、服务或外部定时任务。

## 控制台与维护

社交页显示心情依据、当前关注、范围内经历、来源与分享记录、后台预算和近期活动。接口沿用控制台认证：`GET /api/social/self`，带修订号的经历 `PATCH`/`DELETE` 和关注结束操作。人格提示词模块包含 `pippi_activity`，可复用现有人格补充及调用快照核查实际输入。

加载旧库只添加空字段，保留关系、Owner、聊天、绑定、群模式和自定义人格。损坏的新字段拒绝静默清空或重置预算。备份和恢复沿用 profiles 分片；代码回退应关闭自主阅读并保留最新业务库，不可回灌部署前数据覆盖新消息。

`npm run social:v2:verify` 覆盖来源和权限、范围隔离、版本冲突、校正删除、预算和崩溃恢复、终止和群模式、真实发送确认、旧接话与控制台。`npm run osu:search:verify` 验证论坛首批/后续、地址/大小/期限以及前台阅读写入和发送确认。测试使用隔离目录和模拟发送；真实 API/模型验收不向 QQ 发送测试消息。
