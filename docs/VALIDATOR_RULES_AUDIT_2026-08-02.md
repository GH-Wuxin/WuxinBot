# Validator 规则审计与减法清单（2026-08-02）

依据：用户指令"立即停止基于单词、短语、否定前缀和修辞表达的 validator/Prompt 补丁迭代"，对 `server/osu/analyzer.ts` 中全部 validator 规则逐条分类。

分类约定：
- **硬**：可机械证明的硬事实错误，保留（对应允许清单：输入外数字、数字与字段绑定、Mod 精确/包含关系、PP+ raw/normalized 混淆、缺失数据被编造、混入其他玩家、结构损坏、可直接证明的因果事实冲突）。
- **灰**：需要语义理解才能判断，删除，交给 LLM reviewer（reviewer 当前只记录意见，不重写）。
- **文风**：纯文风/措辞/禁词判断，删除。

## E. 最终保留的机械 validator 边界（对照用户允许清单）

1. 输入外数字（A28/B7/B39/B43/B45 等）
2. 数字与字段绑定（B40/B42）
3. Mod 精确组合及包含关系（A7/B11/B55/B57/B58/B59/B63/B65）
4. PP+ raw/normalized 混淆（B40-B42）
5. 缺失数据被编造（B14/B24/B26/B27/B53；A20 谱面内容）
6. 混入其他玩家/身份（A16/A17/B1/B2/B3/B8/B13/A3/A8）
7. 报告结构损坏（A1/A2/A19/A22/B4/C1/C3/C4/C6）
8. 明确、完整、可直接证明的因果事实冲突（A13/B47/B48/B50/B56/B65；Recent 空断言）

删除后，"敢开 HR""还没定型""这份专注""反复打磨""舒适区""手感"等表达**不得**触发机械拒绝；语义质量由 reviewer 记录意见供人工审计。
