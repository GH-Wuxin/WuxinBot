# 功能、消息来源与回复流程

pippi 可以在对话中调用工具查询自己的功能和发送记录。模型自行决定是否查询；完整能力目录和最近自发消息不在每轮提示中自动加载。正常聊天历史与用户明确引用的消息仍会提供必要上下文。

## 查询功能

`inspect_capabilities` 根据当前注册的指令、工具和公共模块生成目录，再按身份、群模式和开关返回状态。默认返回概览；需要详细条目时用 `view=entries`，将返回的 `nextOffset` 作为下一次的 `offset` 继续查询，也可按 `query`、`id` 查找。

目录说明功能，不授予执行权限。Owner 私有指令的详细说明只在 Owner 私聊中提供；实际执行时仍需核验权限。可问：“你现在能做什么？”“这个群能用随机发图吗？”

## 查询消息

`inspect_message` 用于核对当前会话中的单条消息、作者、引用归属和图片数量。`include_summary=true` 可为这一条消息的待完成摘要等待最多 5 秒；默认不等待。`recent_self=true` 只提供最近少量记录。

要查更早的自发消息或详细发送原因，使用 `inspect_own_messages`：

| 参数 | 用途 |
| --- | --- |
| `message_id` | 按 QQ 消息编号查询 |
| `record_id` | 按档案 UUID 精确查询 |
| `before` | 接上次的 `next_cursor` 向前翻页 |
| `source` | 精确匹配来源链最后一个模块；不清楚标识时可不填 |
| `since`、`until` | ISO 时间范围 |
| `limit` | 每页 1–20 条，默认 5 条；实际结果还受返回长度限制 |
| `include_unconfirmed` | 列表中加入失败、待确认和结果未知的发送尝试 |

记录包含实际模块和操作、外部 Bot 或内部执行者、发送原因、原始触发人或事件、目的地、回应对象、原生引用、@、时间及发送回执。随机图可以由某人的消息触发，同时属于群内发送，不能把触发者直接当成回应对象。

QQ 消息编号可能复用。档案保留不同发送的 UUID，按平台编号查询存在歧义时会提示，并返回最近一条；可以按时间翻页再用 UUID 精确区分。

## 记录与隐私

发送前记录尝试，收到回执后更新结果。每段消息各自记录；失败或无法确认的发送不会被说成已送达。自己账号的回声用于补充回执，不重新当作群友消息进入聊天。

完整档案保存在 `own-messages.sqlite`。滚动聊天记录只保存必要内容和档案引用；普通聊天记录因容量限制自动裁剪后，发送档案仍能分页查询。某个存储暂时不可用时，另一份记录尽量保留可恢复信息，后台再核对。记录失败不应阻止发送，也不应导致重复发送。

宿主限定当前账号和会话，模型不能指定其他群或私聊读取记录，私聊消息查询仅向 Owner 开放。跨会话转发会隐藏原会话身份和内容。工具返回经过筛选的字段，不提供密钥、完整配置、媒体地址或本机路径。

旧记录缺少的执行者、发送原因和对象保持 `legacy` 或 `unknown`。转发卡片内显示的作者是声明信息，不代表平台已核验其身份。原因字段记录执行事实，不保存隐藏的模型推理。

业务备份会配套保存 SQLite 档案。清空会话同时清理对应档案，并防止迟到回声或后台补录重新恢复已删除内容。备份文件的保留方法见 [README](../README.md#数据与隐私)。

## 回复与后台整理

启用社交功能后，直接对话可在一次前台调用中完成参与判断和正文生成。关系与经历更新在后台检查来源及版本，再写入状态。普通对话不等待所有快捷查询摘要或后台整理完成。

被 @ 的较长请求可以由模型选择先发简短回应，再继续生成答案。工具等待期间也可以发送有限的进度提示。只有确认成功的发送才标为已送达，模型思考和未完成草稿不会直接发到 QQ。段落和较长内容按现有文字或合并转发方式交付。

`settings.pippiFastReplies=false` 可使用分离的参与评估流程；`settings.pippiProgressReplies=false` 可关闭阶段回复。对应环境变量为 `PIPPI_FAST_REPLIES=0` 和 `PIPPI_PROGRESS_REPLIES=0`。节能模式使用自己的简化流程，见 [节能模式](TOKEN_SAVING.md)。

## 扩展与验证

新指令和工具复用现有注册元数据。新的公共自动模块需在实现旁调用 `registerPublicFeature`，新的自动发送入口需通过 `sourceSender` 或 `sourceDetails` 提供真实来源和原因。缺少声明的发送标为未知，并计入 `/api/health` 的 `ownMessageArchive` 诊断。

主要实现见 [功能注册](../server/bot/features.ts)、[查询接口](../server/bot/ownMessageInspection.ts)、[来源字段](../server/messageProvenance.ts)和[发送记录](../server/messageFacts.ts)。

```powershell
npm run pippi:awareness:verify
npm run social:v2:verify
npm run backup:verify
```

验证覆盖回声竞态、编号复用、权限隔离、分页、重启、存储故障、备份恢复、删除后迟到事件，以及按需工具调用和回复流程。
