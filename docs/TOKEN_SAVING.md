# Token 节能模式

总览页顶部的「开启节能模式」按钮立即保存，无需重启。只保存 `tokenSavingMode`，不覆盖原来的画像阈值、上下文、思考或自主阅读配置；关闭后恢复原策略。新安装默认关闭。

本版重点是保留低频画像更新，并将自然接话评估收缩为普通门控。

| 项目 | 节能时的生效规则 |
| --- | --- |
| 个人画像首次形成 | 可用记录至少 30 条，同时不低于原有效门槛的 3 倍 |
| 个人画像后续更新 | 新可用记录至少 120 条，同时不低于原有效更新门槛的 4 倍；同一人尝试间隔至少 6 小时 |
| 群画像 | 门槛提高到原值的 4 倍且至少 200 条；默认 80 → 320；间隔至少 6 小时 |
| 群友关系画像 | 100 次互动候选计数、间隔至少 6 小时；仅检查当前有新互动的关系 |
| 接话门控 | 至多 8 条短上下文，只输出是否回复和交流对象；low，API 通道输出预算 512 Token（含思考），无空输出/SDK 重试 |
| 普通自然参与 | 每群每 10 分钟最多一次、每小时最多 6 次；明确请求和正在进行的对话沿用原有回复权限与频率边界 |
| 生成 | 工具循环最多 2 轮；正常回复仍使用 Pippi 人格和已有关联状态；自动 high/max 档位收为 low |

普通门控不写好感、熟悉度、会话心情或 Pippi 自身经历；已有数据继续保留和用于表达。Owner 的真实明确请求可直接跳过模型门控，正常指令优先级与取消来源核验仍在代码中执行。被提到名字的消息继续由模型判断对象，不用关键词规则替代语义。

画像仍积累真实样本，达到条件会自动更新，Owner 手动更新可直接执行。节能时暂停后台画像补偿扫描，只在新增交流时触发；更新期间新来的记录不会被当作已经消化而清零。画像失败保留证据计数和旧画像，并受间隔限制；群/关系尝试时间持久化到 profiles 分片，重启不会立即反复尝试。

关系画像原来会在每条消息之后扫描所有已达门槛的关系，失败后下一条消息继续触发。本次改为只处理当前群、当前参与者的新互动；正常模式失败至少等待 30 分钟，成功后的正常阈值策略保留。

自主阅读、自动图片记忆摘要、升级短句生成和表情失败润色在节能期间暂停。前台主动请求的看图、官方资料检索及确定性 osu! 命令保留。普通聊天历史最多 12 条，关闭额外旧群史扩展，Owner 私聊历史字符预算最多 8,000；当前请求和直接引用仍由原流程提供。

API 请求有包含思考的生成上限，最多 2,048 Token；原本更短的非思考请求沿用更低上限，不自动撤掉限制或重试空输出。Codex App Server 没有硬输出上限能力，使用 low 档位与调用次数限制，不声称能强制限制其输出 Token。本版没有新增全局每日扣费账本。

节能模式遇到 HTTP 401/402/403 或供应商结构化的余额/额度不足错误后，同一通道停止重复调用 10 分钟；更换相关 API 配置后可重新尝试。它不根据聊天内容或模型文字推断账户余额。

自动回归使用本地模拟接口、隔离数据和无头浏览器，不需要用户的真实 API。`npm run token-saving:verify` 覆盖门控无状态写入、Owner、画像持续更新/间隔、并发计数、关系失败退避、无余额停止请求、总览开关保存与失败反馈，并纳入 `npm run check`。
